# 视觉小说游戏框架 - 项目宪法

**版本**: v1.0.0  
**生效日期**: 2026-04-05  
**最后修订**: 2026-04-05  

---

## 项目愿景

构建一个轻量级、高性能、易扩展的视觉小说游戏框架，让创作者专注于故事创作，而非技术实现。

---

## 核心原则

### 原则 1：故事优先 (Story First)

**名称**: STORY_FIRST  
**等级**: MUST  

**描述**:  
框架的所有设计决策必须优先考虑故事创作体验。技术实现应该隐形，让读者完全沉浸在故事中。

**非协商规则**:
- 页面加载时间不得超过 2 秒
- 图片生成不得阻塞内容显示
- 交互设计必须简化，不得干扰阅读流程
- 所有技术细节对创作者透明

**违反后果**: 任何违反此原则的设计必须被拒绝或重构。

---

### 原则 2：数据驱动 (Data-Driven)

**名称**: DATA_DRIVEN  
**等级**: MUST  

**描述**:  
所有内容（故事、选择、图片）必须通过 JSON 数据文件配置，无需修改代码即可创作新小说。

**非协商规则**:
- 小说内容必须完全由 JSON 文件定义
- 不得在代码中硬编码任何故事内容
- 数据文件路径必须使用相对路径
- 数据结构必须支持章节 - 节 - 页三层结构

**违反后果**: 代码与数据耦合的实现必须重构。

---

### 原则 3：响应式优先 (Responsive First)

**名称**: RESPONSIVE_FIRST  
**等级**: MUST  

**描述**:  
框架必须在 PC 和移动端都能提供优秀的阅读体验，响应式设计是核心要求而非附加功能。

**非协商规则**:
- 必须支持 320px - 1920px 宽度范围
- 移动端触摸交互必须优化
- 图片必须自适应不同屏幕尺寸
- 字体大小必须根据屏幕自动调整

**违反后果**: 不支持响应式的组件不得合并。

---

### 原则 4：AI 增强 (AI-Enhanced)

**名称**: AI_ENHANCED  
**等级**: MUST  

**描述**:  
框架必须深度集成 AI 图像生成能力，帮助创作者快速生成视觉素材，降低创作门槛。

**非协商规则**:
- 必须使用「千问 - 文生图」Skill 调用阿里云百炼 API
- 每次生图必须包含小说基础环境设定（tags）
- 必须支持手动上传图片作为补充
- 生成的图片必须下载到本地项目目录存储

**违反后果**: 缺少 AI 生图功能的版本不完整。

---

### 原则 5：零配置启动 (Zero Config)

**名称**: ZERO_CONFIG  
**等级**: SHOULD  

**描述**:  
创作者应该能够在 5 分钟内开始创作，无需复杂的环境配置。

**非协商规则**:
- 开发服务器一键启动
- 默认配置满足 90% 场景
- 错误信息必须清晰易懂
- 提供完整的示例小说

**违反后果**: 配置复杂度影响用户体验的问题应优先解决。

---

### 原则 6：类型安全 (Type Safe)

**名称**: TYPE_SAFE  
**等级**: MUST  

**描述**:  
框架必须使用 TypeScript 提供完整的类型定义，确保数据结构的正确性和开发体验。

**非协商规则**:
- 所有数据结构必须有 TypeScript 类型定义
- 不得使用 `any` 类型绕过类型检查
- JSON 数据结构必须与类型定义一致
- 类型错误必须在编译时发现

**违反后果**: 类型不安全的代码不得合并。

---

### 原则 7：文档即代码 (Docs as Code)

**名称**: DOCS_AS_CODE  
**等级**: SHOULD  

**描述**:  
规范文档与代码同等重要，每个功能模块必须有对应的 spec、plan、task 文档。

**非协商规则**:
- 新功能必须先写 spec 再实现
- 文档变更必须与代码变更同步
- 文档必须使用 Markdown 格式
- 文档必须存放在 specs/ 目录

**违反后果**: 缺少文档的功能视为未完成。

---

## 技术栈原则

### 前端框架
- **必须使用**: Vue 3 + TypeScript
- **构建工具**: Vite
- **样式方案**: CSS + CSS Variables（不使用重型 CSS 框架）

### 开发服务器
- **Host**: 0.0.0.0（支持局域网访问）
- **Port**: 8002
- **协议**: HTTP（开发环境）

### AI 服务
- **图像生成**: 千问 - 文生图 Skill（阿里云百炼 API）
- **备用方案**: 支持手动上传图片

---

## 数据结构原则

### 路径规则
1. 所有 JSON 中的路径必须是**相对路径**
2. 相对路径的基准是**当前 JSON 文件所在目录**
3. 图片资源统一存放在 `images/` 子目录

### 命名规则
1. 章、节、页的 ID 必须使用数字编号（01, 02, 03...）
2. 文件命名必须使用小写 + 数字
3. 目录命名使用 `<小说英文名>` 格式

### 内容结构
1. 小说必须按 **章→节→页** 三层结构组织
2. 每页必须包含：id, title, background, content, selections
3. 选择支必须包含：icon, text, to（目标页 ID）

---

## 质量门禁

### 性能指标
- 首屏加载时间：≤ 2 秒
- 页面切换时间：≤ 500 毫秒
- 图片生成等待：显示占位符，不阻塞 UI

### 代码质量
- TypeScript 编译错误：0
- ESLint 错误：0
- 类型安全：禁止使用 `any`

### 测试要求
- 核心功能必须有手动测试验证
- 每次变更必须验证小说列表、阅读、选择功能

---

## 版本管理

### 语义化版本
- **MAJOR**: 破坏性变更（数据结构变更、API 变更）
- **MINOR**: 向后兼容的功能新增
- **PATCH**: 向后兼容的问题修复

### 分支策略
- `main`: 稳定版本
- `develop`: 开发分支
- `feature/*`: 功能分支

---

## 合规性检查

每个功能开发前必须回答：
1. 是否符合"故事优先"原则？
2. 是否遵循数据驱动设计？
3. 是否支持响应式布局？
4. 是否有完整的类型定义？
5. 是否有对应的规范文档？

**任何一项为"否"的功能不得进入实现阶段。**
