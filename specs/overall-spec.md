# 视觉小说游戏框架 - 整体规格文档

**版本**: v1.0.0  
**日期**: 2026-04-05  
**状态**: 初稿  

---

## 1. 概述

### 1.1 项目简介

视觉小说游戏框架是一个基于 Web 的轻量级互动小说引擎，支持创作者通过 JSON 数据文件快速构建带有分支选择和 AI 生成图像的视觉小说。

### 1.2 目标用户

- **小说创作者**: 无需编程经验，通过编写 JSON 即可创作互动小说
- **独立游戏开发者**: 快速原型验证，低成本试错
- **内容创作者**: 使用 Skill 生成 AI 图像，降低美术成本

### 1.3 核心价值

1. **零编程门槛**: 创作者只需关注故事内容
2. **AI 增强创作**: 使用 Skill 调用阿里云百炼 API 生成图像
3. **跨平台阅读**: PC 和移动端统一体验
4. **数据驱动**: 内容与代码完全分离

## 2. 功能需求

### 2.1 小说列表 (FR-BOOKS)

**FR-BOOKS-001**: 系统必须显示所有可用小说的列表  
- **验收标准**: 
  - 每部小说显示封面、标题、副标题
  - 每部小说项右下角有"开始"按钮
  - 列表支持滚动（小说数量超过一屏）

**FR-BOOKS-002**: 用户点击"开始"按钮后进入对应小说  
- **验收标准**: 
  - 点击后 500ms 内加载小说第一页
  - 加载过程显示过渡动画

### 2.2 小说阅读 (FR-READING)

**FR-READING-001**: 系统必须显示当前页的内容  
- **验收标准**: 
  - 显示背景图片
  - 显示文字内容
  - 显示页标题（可选）

**FR-READING-002**: 系统必须支持分支选择  
- **验收标准**: 
  - 显示所有可选选项
  - 每个选项显示 icon 和 text
  - 点击选项后跳转到目标页

**FR-READING-003**: 系统必须记录阅读进度  
- **验收标准**: 
  - 刷新页面后回到当前页
  - 提供"重新开始"选项

### 2.3 图片管理 (FR-IMAGE)

**FR-IMAGE-001**: 系统必须支持 AI 生成背景图  
- **验收标准**: 
  - 使用「千问 - 文生图」Skill 生成图片
  - 生图时自动带上小说 tags 作为上下文
  - 生成成功后立即下载到本地存储

**FR-IMAGE-002**: 系统必须支持手动上传图片  
- **验收标准**: 
  - 支持 JPG、PNG、WEBP 格式
  - 图片自动压缩到合适尺寸
  - 上传成功后可在 JSON 中引用

**FR-IMAGE-003**: 系统必须本地存储生成的图片  
- **验收标准**: 
  - 图片存储路径：`public/data/<小说名>/images/backgrounds/`
  - 使用描述性文件名
  - JSON 中引用本地路径而非远程 URL

### 2.4 响应式布局 (FR-RESPONSIVE)

**FR-RESPONSIVE-001**: 系统必须支持移动端（320px - 768px）  
- **验收标准**: 
  - 文字大小自动适配
  - 触摸区域 ≥ 44px
  - 横向滚动禁用

**FR-RESPONSIVE-002**: 系统必须支持平板端（768px - 1024px）  
- **验收标准**: 
  - 布局自适应
  - 图片比例保持

**FR-RESPONSIVE-003**: 系统必须支持桌面端（1024px - 1920px）  
- **验收标准**: 
  - 最大宽度限制
  - 居中显示

### 2.5 数据加载 (FR-DATA)

**FR-DATA-001**: 系统必须从 public/data/books.json 加载小说列表  
- **验收标准**: 
  - 文件不存在时显示友好提示
  - 支持热更新（修改后刷新即生效）

**FR-DATA-002**: 系统必须根据 book.json 加载小说结构  
- **验收标准**: 
  - 正确解析章 - 节 - 页结构
  - 路径解析正确

**FR-DATA-003**: 系统必须按需加载页面 JSON  
- **验收标准**: 
  - 只加载当前页数据
  - 预加载下一页（可选优化）

---

### 2.6 HP 机制 (FR-HP)

**FR-HP-001**: 系统必须显示当前血量  
- **验收标准**: 
  - 页面左上角显示红心图标和血量数值
  - 格式：❤️ 10/10 或 ❤️ 10
  - 血量变化时有视觉反馈

**FR-HP-002**: 系统必须在进入页面时应用血量变化  
- **验收标准**: 
  - 页面 JSON 的 `hp` 字段为负数时扣血
  - 页面 JSON 的 `hp` 字段为正数时加血
  - 血量不超过最大值（100）
  - 血量不低于 0

**FR-HP-003**: 系统必须处理死亡状态  
- **验收标准**: 
  - 血量 <= 0 时触发死亡结局
  - 显示死亡结局页面
  - 提供"重新开始"选项

---

### 2.7 物品机制 (FR-ITEMS)

**FR-ITEMS-001**: 系统必须显示当前物品  
- **验收标准**: 
  - 页面右上角显示物品图标
  - 可区分可食用物品（绿色框）
  - 点击可食用物品可食用并加血

**FR-ITEMS-002**: 系统必须支持拾取物品  
- **验收标准**: 
  - 页面中显示可拾取物品列表
  - 多个物品时只能选择一个或都不选
  - 拾取后物品加入背包

**FR-ITEMS-003**: 系统必须支持物品锁定选项  
- **验收标准**: 
  - 选择支的 `use` 字段指定所需物品
  - 只有拥有该物品时才显示此选项
  - 没有物品时选项完全隐藏

**FR-ITEMS-004**: 系统必须支持使用物品  
- **验收标准**: 
  - 食物类物品可食用
  - 食用后物品消失
  - 食用后按物品 `hp` 值加血

---

### 2.8 阅读体验 (FR-READING-UX)

**FR-READING-UX-001**: 系统必须使用打字效果呈现内容  
- **验收标准**: 
  - 文字逐字显示
  - 打字速度适中（约 50-100ms/字）
  - 支持跳过打字动画

**FR-READING-UX-002**: 系统必须在打字完成后显示选择框  
- **验收标准**: 
  - 打字期间选择框隐藏
  - 打字完成后选择框淡入显示
  - 动画流畅自然

## 3. 非功能需求

### 3.1 性能需求 (NFR-PERF)

**NFR-PERF-001**: 首屏加载时间  
- **指标**: ≤ 2 秒（3G 网络）
- **测量方式**: Chrome DevTools Performance

**NFR-PERF-002**: 页面切换时间  
- **指标**: ≤ 500 毫秒
- **测量方式**: 点击到内容显示的时间

**NFR-PERF-003**: 图片生成等待  
- **指标**: 显示加载状态，不阻塞 UI
- **测量方式**: 用户感知等待时间

### 3.2 可用性需求 (NFR-USABILITY)

**NFR-USABILITY-001**: 零配置启动  
- **指标**: 新用户 5 分钟内完成首次运行
- **测量方式**: 用户测试

**NFR-USABILITY-002**: 错误提示友好性  
- **指标**: 所有错误信息包含解决建议
- **测量方式**: 代码审查

### 3.3 兼容性需求 (NFR-COMPAT)

**NFR-COMPAT-001**: 浏览器兼容性  
- **指标**: 支持 Chrome 90+, Safari 14+, Firefox 88+
- **测量方式**: BrowserStack 测试

**NFR-COMPAT-002**: 设备兼容性  
- **指标**: 支持 iOS 13+, Android 10+
- **测量方式**: 真机测试

### 3.4 可维护性需求 (NFR-MAINT)

**NFR-MAINT-001**: 类型覆盖率  
- **指标**: TypeScript 覆盖率 100%
- **测量方式**: tsc --noEmit 零错误

**NFR-MAINT-002**: 文档完整性  
- **指标**: 每个模块有 spec/plan/task 文档
- **测量方式**: 检查 specs/ 目录

**场景 1: 开始阅读**

用户打开网站
→ 看到小说列表

## 5. 数据结构

### 5.1 小说列表 (books.json)

```json
{
  "books": [
    {
      "title": "小说标题",
      "subtitle": "小说子标题",
      "cover": "<封面图片相对路径>",
      "path": "<小说英文名>/book.json"
    }
  ]
}
```

### 5.2 小说框架 (book.json)

```json
{
  "title": "小说标题",
  "subtitle": "小说子标题",
  "cover": "<封面图片相对路径>",
  "tags": "小说的基础环境设定，用于 AI 生图",
  "chapters": [
    {
      "id": "01",
      "title": "章标题",
      "sections": [
        {
          "id": "01-01",
          "title": "节标题",
          "pages": [
            {
              "id": "01-01-001",
              "title": "页标题",
              "json": "01/01/001.json"
            }
          ]
        }
      ]
    }
  ],
  "items": [
    {
      "id": "bread",
      "name": "面包",
      "type": "food",
      "hp": 2,
      "icon": "🍞"
    },
    {
      "id": "gun",
      "name": "手枪",
      "type": "weapon",
      "icon": "🔫"
    }
  ]
}
```

### 5.3 页面内容 (XX/YY/ZZ.json)

```json
{
  "id": "01-01-001",
  "title": "页标题",
  "background": "<背景图片相对路径>",
  "content": "该页的文字内容",
  "hp": -1,
  "items": ["bread"],
  "selections": [
    {
      "icon": "🚪",
      "text": "打开门",
      "to": "01-01-002"
    },
    {
      "icon": "🔑",
      "text": "用钥匙开门",
      "use": "key-for-01-01-001",
      "to": "01-01-003"
    }
  ]
}
```

**新增字段说明**:
- `hp`: 进入此页面时的血量变化（正数加血，负数扣血）
- `items`: 页面中可拾取的物品 ID 列表
- `use`: 选择支需要的物品 ID（只有拥有该物品才显示此选项）

## 6. 边界情况

### 6.1 数据缺失

**EDGE-DATA-001**: books.json 不存在  
- **处理**: 显示"暂无可用小说"提示
- **恢复**: 文件添加后刷新自动恢复

**EDGE-DATA-002**: 页面 JSON 不存在  
- **处理**: 显示"内容加载中..."并尝试重新加载
- **恢复**: 文件添加后自动继续

**EDGE-DATA-003**: 图片路径无效  
- **处理**: 显示默认背景色
- **恢复**: 图片上传后自动替换

### 6.2 网络异常

**EDGE-NET-001**: AI 生图失败  
- **处理**: 显示"生成失败，请重试"
- **恢复**: 提供手动重试按钮

### 6.3 用户错误

**EDGE-USER-001**: 选择支目标页不存在  
- **处理**: 显示错误提示并返回上一页
- **预防**: 开发时提供链接校验工具

## 8. 假设与依赖

### 8.1 技术假设

- 用户浏览器支持 ES6+
- 开发环境有 Node.js 16+
- bailian-image 服务可用

### 8.2 外部依赖

- **Vite**: 构建工具
- **Vue 3**: 前端框架
- **TypeScript**: 类型系统
- **阿里云百炼 API**: AI 图像生成（通过千问 - 文生图 Skill 调用）

### 8.3 项目假设

- 创作者具备基础 JSON 编辑能力
- 小说内容不涉及版权敏感素材
- AI 生成图片满足基本质量要求
